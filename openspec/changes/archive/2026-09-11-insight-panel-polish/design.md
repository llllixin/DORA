## Context

- **判断列的两个数据来源**：① `/api/dora/chat`(SSE) 的 `answer.text`（`backend/app/routers.py::_compose_answer`，意图规则分类；why 分支固定拼 `「title」的判断来自引擎：desc` → `主要影响因素：…` → `进一步定位：…`，再**无条件**追加 `下一步建议：…` 与 `可参考历史先例：…`／`历史知识库暂无同指标先例。`）；② chat 失败时前端用 `semantics` 拼兜底句。
- **同一页面已有专属区块**：左栏归因卡（`semantics.causeA/causeB`）、下方「下一步建议」面板（`semantics.next`）、左栏事实行（关键数值/触发条件/证据来源）。判断列与三者存在事实上的**同源重复**。
- **本轮同批的其它展示层问题**：① 图表 `preserveAspectRatio="none"` 会让图形随容器宽高比拉伸（同一洞察在不同宽度/容器下图形变形、视觉高度不稳定）；② 纵轴刻度按 `toFixed(0)` 取整在大数值区间会出现**相邻刻度标签重复**（如 `20% / 20%`）；③ 洞察列表常驻 300px 占位；④ 脉搏页「专家团能力说明」是不可交互的单行静态文案，而 `data.ts` 已有 `capabilities.专家团` + `autoExpertNotes` 数据。
- **约束/红线**：判断与数字不残留页面（D004）——判断列文本必须逐字来自引擎/chat 原文，前端只能**拆分与取舍**，不能改写或生成；不引图表库（SVG 手绘延续）；AskBar/F8、图表引擎驱动 F11 不在范围内；Pulse 专家内容在 E3 (`expert-registry-ui`) 之前只读 `data.ts` 离线镜像。
- **既有前端机制**：`splitVerdict` 把长文拆「结论（首句）+ 补充」；W2 已固化「字段 → 来源 → 降级文案」盘点表注释；`.judge-grid` 两栏等宽等高（`align-items:stretch`）。

## Goals / Non-Goals

**Goals:**
- 判断列只表达「为什么」：结论句（+ 判断独占的补充行）+ 置信度；同屏内信息**只出现一次**。
- 归因/下一步/先例三类信息**换位而非删除**，且落在语义一致的区块。
- 离线与 `judge.err` 兜底态保持诚实（不因去重复而新增假值）。
- 本轮同批展示层问题一次收口：图表不变形、刻度标签不重复、列表不常驻占位、专家说明可交互。

**Non-Goals:**
- 不改后端 chat 的意图分类、模板文案与事件契约（`number_source="engine"` 数字锁继续有效）。
- 不在判断列生成任何前端新文案/新数字（不做「影响面/可干预性」等填白字段）。
- 不改造折叠以外的交互，不动证据链入口、AskBar 提交链路。
- 不把专家团 chips 接到 registry（E3 范围）；不持久化抽屉/展开态。

## Decisions

### D1｜去复述放在**展示层**（前端行归类），后端不动
- 前端新增 `belongsElsewhere` 前缀归类，命中行不进判断列。
- **为什么**：`_compose_answer` 的消费者不止判断列——AskBar 的 Dora Chat 里问「为什么…」得到含下一步建议的完整答案**是合理的对话行为**；且 `tests/agent_check.py` 的答案契约/数字锁钉在现有结构上，改后端 = 动契约 + 动门禁。
- **备选（否决）**：后端按 `page='insight'` 或 intent 裁剪 next/refs 段 → 需要为页面分叉 chat 语义，让页面绑架对话面；且离线兜底态无法覆盖。

### D2｜归类命中 = **不显示**（不是「默认折叠、展开可见」）
- 判断列永不复述其它区块的行，展开也只揭示「判断独占」的行。
- **为什么**：若展开后仍能看到「下一步建议」，用户仍会认为判断列在替下一步建议重复占位（正是本次问题的观感来源）；而这三类信息全部有专属落点，判断列的「原文全文可读」不是需求（另有证据链与「↻ 重新解释」）。
- **代价/后果**：模板答案下「展开补充说明」通常不出现，判断列 = 结论句 + 置信度；当 AI/引擎返回**非模板结构**（多句判断独占文本）时，补充说明与折叠自动生效（逻辑保留，非死代码）。

### D3｜「历史知识库暂无同指标先例」落进左栏新行「历史先例」
- chat 成功（`!judge.loading && !judge.err`）且 `references` 为空 → 左栏显示 `历史先例：暂无同指标先例`（`ev-none` 次要色）；命中 → `先例标题（code）`（与既有实现一致）。
- **为什么**：这是**检索事实**（references 来自真实 `repo.search_knowledge`），不是判断；与命中态同处一行，语义连续；chat 不可用时不显示（不把「没查到」伪装成判断依据）。
- **备选（否决）**：直接丢弃 → 丢失「无先例」这一事实信息。

### D4｜布局：保持两栏等宽等高 + 置信度贴卡片底
- `.verdict-conf{margin-top:auto}`（卡片内 flex 自动吸底）。
- **为什么**：去复述后右栏内容变短，等高会被拉长；「结论在顶、置信度在底」使卡片底部仍有落点，空白读作留白而非缺内容，且与左栏「标题在顶、内容在下」的骨架呼应。
- **备选（用户已否决）**：`.judge-grid{align-items:start}`（卡片按内容高度，消除内部空白）→ 两卡高度不齐；2026-09-11 用户明确选择保持等高。
- **备选（否决）**：给判断列塞新内容填白（影响面/可干预性等）→ 引擎无对应字段，属编造，触 D004 红线。

### D5｜判断数据源 = `/api/dora/chat`(SSE)，不在前端编判断
- 新增 `doraApi.askDora(question, {insightId, page})`：逐事件解析 `thought_step/tool_call/evidence/answer/done`，取 `answer.text` + `references`（保留 `intent/runId` 备用），20s 超时 + `AbortController`；失败/离线抛错 → `judge.err`，判断列落到「引擎 `semantics` 兜底句 + `verdict-note` 显式说明」。
- **为什么**：判断必须在后端（D004），前端只表达；SSE 让「思考/工具调用」链路可扩展（Chat 面日后复用同一客户端）。
- **备选（否决）**：前端按 `semantics` 自己拼「判断」→ 前端生成判断，违反 D004。用非流式端点 → 后端只提供 SSE。

### D6｜图表等比（`xMidYMid meet`）+ 纵轴刻度小数位按间距决定
- 5 处 `preserveAspectRatio="none"` → `"xMidYMid meet"`；新增 `tickStep=(mx-mn)/5` → `dec`（`≥1→0 / ≥.1→1 / 否则 2`），`tick()` 归一小数值 `-0`，`grid` 用它渲染刻度。
- **为什么**：`none` 会非等比缩放坐标系（圆变椭圆、字号/线宽变形，容器高度变化时图形高度漂移）；刻度重复是「取整到 0 位」在大数值区间（如 18–20%）的必然结果。
- **代价**：等比后在超宽容器里图形居中、左右留白（高度由容器决定）——优于变形。
- **备选（否决）**：按容器宽度做响应式坐标重算（改动面大、需测量 DOM）；引图表库（违反零依赖取向）。

### D7｜洞察列表改可折叠抽屉（视图态，不持久化）
- `.insight-shell` 由 grid 改 flex；`.insight-drawer` 宽 300px、收起 46px（只留切换按钮）；`listOpen` 默认展开；换洞察时只重置判断列展开态，不重置抽屉。
- **为什么**：详情页是主体，列表只是导航；收起态把宽度让给图表与证据。
- **备选（否决）**：持久化到 localStorage → 新增状态源 + 跨页一致性成本，收益小。

### D8｜脉搏页「专家团能力说明」改可点 chips + 移除「?」提示
- chips 数据来自 `data.ts`（`capabilities.专家团` + `autoExpertNotes`），切换展示「名称：说明 + 备注」；同时移除「持续关注」卡片标题的 `?` note（`.summary-card .q` 规则以注释说明删除原因）。
- **为什么**：原实现是不可交互的单行写死文案，而离线镜像里已有结构化数据；`?` 依赖 title 悬浮（移动端不可达）且与 `desc` 信息重复。
- **备选（否决）**：本 change 直接接 `GET /api/experts` → 端点尚未实现（E1 范围），会让本 change 变成跨 change 依赖。
- **退出条件**：E3（`expert-registry-ui`）落地后，chips 数据源切 registry 并删 `data.ts` 镜像；本 change 只到「用镜像 + 标注边界」。

## Risks / Trade-offs

- [判断列在模板答案下内容稀薄（1 句 + 置信度）] → 结论句保留字号/字重突出，置信度贴底形成骨架；若 LLM 侧日后产出多句判断，`ownRest` 自动恢复补充说明（无需再改）。
- [行归类依赖文案前缀正则，后端改词即失效] → 正则集中在一处并附示例原文注释；归档前跑 CDP 断言。失效表现是「判断列多出/少一行」（可见退化），不是静默错误。
- [左栏新增「历史先例」行可能被视为噪音] → 仅在检索为空时出现 + 次要色；用户 review 可否决（回退 = 删除该分支，不影响其它决策）。
- [信息换位后用户一时找不到] → 三处落点都在同一屏内（左栏归因卡 / 左栏先例行 / 下方面板），proposal 已给「零丢失」对照。
- [图表等比后宽容器中左右留白（图形居中）] → 接受：留白优于变形；若日后要求填满，仅对几何类图（bubble/step）单独取舍，不动坐标算法。
- [Pulse chips 数据来自 `data.ts` 镜像，与未来 registry 形成双源] → 已在 §4 E3（`expert-registry-ui`）登记为切换任务；本 change 不新增第三处数据源。
- [askDora 的 SSE 解析依赖 `\n\n` 分帧约定] → 按空行分块 + 容错读取；后端事件格式有 `tests/agent_check.py` 门禁；任何异常一律走降级（不空白、不假值）。
- [判断列 `judge.err` 与「离线演示」共用同一视觉（`verdict-note`）] → 文案已区分「AI 暂不可用，以上为引擎语义兜底」；离线 demo 数据仍有 `semantics`，观感不退化。

## Migration Plan

- 无 DB/契约迁移、无功能开关；回滚 = 还原本轮 5 个前端文件（`InsightPage.tsx` / `PulsePage.tsx` / `InsightChart.tsx` / `doraApi.ts` / `styles.css`，无后端依赖）。
- 生效方式：前端重新构建（`npm run build`；dev 5173 走 HMR，preview 4173 需重建 dist）。
