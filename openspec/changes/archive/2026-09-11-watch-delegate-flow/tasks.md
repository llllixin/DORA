## 反思（归档）

1. **propose 的机制假设必须在 apply 期回代码验证**：D5 写「`load()` 落到 `catch` 即离线」，实测 auto 模式 `apiGet` 永远不抛（内部兜底）→ 改由 `listWatch(onFallback)` 显式上报；这是 apply 期纠正 design 的正例（已记 P015）。
2. **诚实性要推到底**：镜像没有 `status` 就离线不画状态；离线时连「当前委托」也不声称（`当前委托 · 未连接后端`）——避免同屏自相矛盾。
3. **同源才敢断言一致**：pill 与 4 个步骤都从同一次 `_watch_card` 派生，才有「不会 pill 说 A、步骤说 B」的断言；反之不使用 `logic`/`value` 字符串嗅探（D003/D004）。
4. **全局 CSS 的源序是隐式契约**：移动端覆盖写在基样式之前 = 静默死规则（P013 第二形态），改样式时先确认同权重规则的书写顺序。
5. **验证工具自身也会互相污染**：并发两个 CDP 驱动共享一个 page target → 视口互相覆盖、两张截图 md5 相同；量测脚本必须串行，并用 PNG 头/`innerWidth` 复核实际视口。
