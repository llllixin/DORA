# Dora · 全流程完整性审计与优化方向（2026-09-07）

> 审计范围：V1–V5 主线（数据→引擎→洞察→Reasoning(LLM)→Watch→Action→验证）全链路 + 工程质量与遗留双源。
> 审计证据：`tests/run_all` **7 段 ALL GREEN**（engine/ingest/reasoning/golden 9/e2e 4case/watch 4节/action 4节）；`npm run build` ✅；`openspec validate --specs --changes` 6/6 ✅；后端日志 0 Traceback；真实 DeepSeek 批量 refresh 9/9（4.9s）。

## 0. 完整性结论

**主线已经闭环且判定诚实**：业务数据（样例/上传）→ 确定性引擎判定洞察 → 模板/LLM 文案（数值锁）→ 变化进持续关注（Watch 委托+升级引用引擎）→ 问题/机会进行动档案（Case 建档→步骤→验证→归档，结果回写不污染判定）。
**尚未完成的是"记录驱动的边界外"**：真实外部动作执行、实时推送、分布式调度、多源/部署等（属设计内候选，不是缺陷）。

## 1. 已发现问题清单（审计发现，按处置分级）

### F 级 · 建议处置
| # | 问题 | 现状/影响 | 处置 |
|---|---|---|---|
| F1 | **静态双源仍在服务端**：`/api/actions*`、`/api/insights` 历史兜底（INSIGHTS）、`/api/evidence` 兜底（EVIDENCE）仍从 `app/data.py` 吐静态 | V4/V5 已真实化，但 e2e Case1/2 仍依赖旧 /actions 契约；易再养成"静态兜底"习惯 | 先改 e2e 与前端 sync 切新 /api/action/cases，再下线静态端点（保留 data.ts 仅作前端离线兜底） |
| F2 | **前端死代码**：doraApi `createFollowup`（旧 `/watch{insightId}` 语义已废弃）与 `executeAction` 无调用点 | 未来误用会 400 且语义误导 | 删除或迁移到新语义并注释 |
| F3 | **类型不诚实**：`listActionCases` 把"无 steps 的列表摘要"当 `ActionCaseDetail[]` 返回（TS 结构缺 steps） | 消费方需隐含"摘要"事实 | 拆 `ActionCaseCard`(摘要) 与 `ActionCaseDetail`(含 steps) 两个 DTO |
| F4 | **seed 档案会被样例重置**：`载入样例`→`run_seed` 用 upsert_seed_case 把 5 个静态档案复位到初始态 | 用户对 seed 档案的执行进度被工厂样例覆盖（自定义档案不受影响） | 明确语义并记录（D 系列）：seed 档案=演示基线，进度入 self 档案才持久；或 sample 只重建"未开始"的 seed |
| F5 | **真实 LLM 路径无门禁**：run_all 钉死 template+空 key（正确），真实网络路径只靠手动冒烟 | 回归风险由 mock（数值锁/无 key fallback）兜底，真实调用不回归 | 可选真实冒烟脚本 `DORA_LLM_API_KEY=…` 单独跑（不进 run_all）；CI 接入留后续 |
| F6 | **Watch 周期调度无持久化队列**：单实例守护线程 60s tick，重启丢到期窗口（靠 last_checked 补跑） | 单实例可接受（D009 推迟 Redis/Celery），多进程部署前必须换 | 记录为候选依赖：Redis/Celery 前身 |
| F7 | **前端无自动刷新**：Watch 列表/档案进度依赖跳页重挂载或按钮动作后的 reload；无轮询/SSE | 跨端变化需手动刷新才可见 | LLM 阶段2 异步/SSE 一并引入轻量轮询（候选 P1） |
| F8 | **AskBar / FollowupCard「追问」仍是 mock**（V3 明确另立能力） | 用户点追问只见占位文案 | 候选：接 DeepSeek 做"带洞察上下文的追问"（规划后开工） |
| F9 | **数字一致性核对未做**（V2 遗留低优先）：引擎输出与页面展示逐字段核对 | 目前各视图均读引擎/DB 同源，风险低但仍需一次人工盘点 | 低优先收尾 |
| F10 | **env 文档小缺口**：backend/.env 实际（llm+DeepSeek）与 .env.example 默认（openai/template）有差异，易误导新环境 | 加注释说明"example=缺省；本地可按需覆盖"，并把实际跑通的 DeepSeek 参数示例补注释 | 随手 docs |

### C 级 · 已知边界（设计内，不做不算缺陷）
- 判定一律引擎：LLM 只动文案；Watch escalate / Action resolved 均不伪造身份（P/D 红线）。
- `resolved` 需人工/工具 verify note；引擎指标恢复只作档案证据，不自动关闭（D031）。
- 支持范围显式：Watch 仅引擎词典指标、Action 仅当前引擎判定集——拒绝即诚实。
- urllib 单 socket 总超时 10s（D030）；单飞/熔断进程内有效（多进程前需集中状态）。

## 2. 优化方向候选（附优先级）

> 规则：功能/优化都先开 OpenSpec change（propose→review→apply→archive）；**另立正式大版本需先 §3D backlog/planning**（见路线图 §3C.6）。

### P0 · 维护整洁（1–2 天，无新功能）——✅ 已完成（迭代 34 `cleanup-static-layer`）
1. **F1 静态双源下线**：/api/actions* 已下线（404）；/insights、/evidence 不再静态兜底（只认引擎/Repository，缺则 404）；e2e Case1/2 改用真实 /action/cases 档案断言；前端 sync 不再拉旧 /actions。data.ts 保留离线演示语义。
2. **F2/F3 已完成**：死代码 createFollowup/executeAction/旧 getActionCase/listActions 已删；Action 列表 ActionCaseCard / 详情 ActionCaseDetail 拆型。
3. **F10 已完成**：.env.example 补 DeepSeek 注释样例。

### P1 · 体验与工程（推荐下一棒）
4. **LLM 刷新阶段 2（异步 job）**（P011/D028/D030 阶段 1 已完成 + Bug1 已收口）：
   - 内容：refresh 提交即回 taskId → `GET /api/reason/tasks/{id}`（running/done/partial + n/m）→ 前端"更新中 n/m"轮询（SSE 可选）；顺带 F7 Watch/档案轻量轮询。
   - 价值：UI 永不被 LLM 阻塞；退出条件：P99 任务完成可见、无 2.6s 类误杀。
5. **F9 数字一致性核对**：引擎输出 ↔ 页面（Pulse/洞察/图表）逐字段盘点一次，产出核对记录。
6. **可观测打点**（P011 L4）：reasoning.llm.latency/errors/fallback/circuit、watch/action 事件数——为阶段 2 与熔断退出条件提供数据。

### P2 · 能力增强（各需先 §3D planning）
7. **工具/Agent 执行层**（D031-1 预留口）：让 Action 步骤可绑定真实外部动作（外呼/建单/改价/查询工具），结果回填 note；先定义"工具契约 + 执行记录（step result 已有）"。
8. **Redis/Celery 调度**（D009 推迟项）：替代 Watch tick/LLM 单飞，多进程/部署前置；scheduler 逻辑已收敛到 watch/scheduler.py，迁移面小。
9. **Docker 全家桶**（搭建文档 37）：frontend/backend/redis 容器化 + `docker compose up` 一条命令（现仅 PG 容器）。
10. **多数据源/上传强化**：多数据集并存、历史版本、换源语义（当前 replace_series=单源）。
11. **AskBar/Dora Chat 追问**（F8）：接 DeepSeek，带洞察上下文（Watch/Insight 页已有 context 槽位）。
12. **生产部署**（搭建文档 38）：Nginx + 静态构建 + worker/scheduler + 日志/监控；对象存储（报告/证据快照）。
