# Dora · 文档地图（职责分层与一致性规则）

> 目的：任何新会话 / 新迭代先看这里，判断「这条信息该写进哪个文件、哪些文件已冻结不该再改」。
> 配套：`.clinerules/project-conventions.md` §0；一致性自检 `cd backend && python3 -m tests.check_docs`。

## 1. 三层模型

- **L0 入口（导航）**：只放「当前一句话 + 指针」，禁止复述清单/表格全文。
  - `AGENT.md`（会话速查，context 恢复入口）
  - `docs/版本路线图.md`（版本看板 hub：当前状态 / 单一事实源导航 / 质量锚点 / 更新约定）
- **L1 事实源（唯一维护点）**：每类状态只允许在这一个文件里改。
  - `docs/历史版本路线.md`：已完成版本（V1–V5 + 收尾迭代 34–38）的历史与 sign-off 索引（只读归档）
  - `docs/持续优化路线.md`：**唯一 backlog**（候选方向 / 遗留小项 / 已选块 W·E / 审查遗留 / 推进顺序）
  - `docs/开发过程记录.md`：迭代流水（只追加「迭代 N」，不含待办）
  - `docs/开发问题与经验.md`：P/D 问题与决策（只进 P/D）
  - `openspec/specs/`：对外行为契约（每 spec 顶部需求来源表）
  - `openspec/changes/`：变更级事实源（proposal/spec/design/tasks）；归档在 `archive/`
- **L2 快照（冻结）**：加「截至 yyyy-mm-dd」标注后不再维护状态；如需补注只在头部快照行追加。
  - `RELEASE_NOTES_V2..V5.md`、`docs/V3..V5_ACCEPTANCE_CHECKLIST.md`、`docs/优化方向.md`、`openspec/changes/archive/`

## 3. 信息主题 → 唯一归属（找/改信息先查这行）

| 主题 | 唯一归属 | 禁止在哪复述 |
|---|---|---|
| 版本是否完成 / sign-off | `历史版本路线.md` §1/§4 | RELEASE_NOTES、验收清单（已冻结，只读） |
| 还差什么 / 下个做什么 | `持续优化路线.md` §2–§6 | AGENT/hub 只能指针化引用 |
| 某个迭代具体干了什么 | `开发过程记录.md`（迭代 N） | 其它文件不得复制清单 |
| 某个取舍为什么 | `开发问题与经验.md` D/P 系列 | design 只放落地细节，理由进 D |
| 系统对外必须做到什么 | `openspec/specs/` | 页面/代码不写死判断 |
| 审计/发布/验收历史 | `优化方向.md` / RELEASE_NOTES / 验收清单（冻结快照） | 不再更新状态 |

## 4. 一致性规则（写文档必须遵守）

1. **状态只进绿文件**（L1）；黄文件（L2 快照）不加状态，只在头部「截至」行补注。
2. **入口只放指针**：AGENT/hub 引用清单一律写 `见 docs/xxx §N`，禁止整段复述。
3. **改文档/归档前跑** `cd backend && python3 -m tests.check_docs`（死链 / 双源待办 / 编号连续性 / ✅ 可回溯）。
4. 若发现两个文件对同一状态表述冲突 → 以唯一归属为准并**顺手修指针文件**，不许两边都改。
5. 快照型重复可接受（历史证据），但必须带日期行，避免被当成活文档。
6. AGENT/hub 允许保留摘要，但只限「当前一句话」；完整清单永远在 L1。

> 已知刻意重复（允许区）：AGENT §3 / hub §2 的状态摘要（≤3 行）；历史版本路线 §4 sign-off 索引表（指向验收清单，不重抄结论）。
