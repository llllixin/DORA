## 迭代 5：页面级数据切 HTTP —— 启动时从 FastAPI 同步领域数据

- **时间**：2026-09-06
- **目标**：四大页面的"领域数据"真正来自后端，而不是继续读死 `data.ts`
- **做法（原位同步，页面零改动）**
  - 页面组件（Pulse/Insight/Action/Watch）是超长压缩单行实现，直接改成"prop 注入 + 加载态"风险高；因此采用**同步器模式**：App 进入主界面后调用 `syncRemoteData()`，探测 `/api/health`，成功则并行拉取 `/api/insights?type=…` ×3、`/api/actions`、`/api/watch`，把结果**原位刷新**到 `data.ts` 导出的同一批数组/对象（`insights.problem` 等用 splice、`actionCases` 用重建 key），再触发一次 React 重渲染 → 页面即显示后端数据，视觉与契约完全一致
  - 后端不可用时**不刷新**（本地 Mock 兜底），前端"无后端也能演示"的承诺继续成立
- **改动文件**
  | 文件 | 说明 |
  |---|---|
  | `frontend/src/services/doraApi.ts` | 新增 `detectApi()` / `isApiLive()` / `listActions()` / `listWatch()` / `syncRemoteData()` |
  | `frontend/src/App.tsx` | 新增 `setSyncTick` 状态与启动同步 `useEffect`（依赖 `dataSrc`，数据就绪后执行并 toast 提示） |
- **验证**：`npm run build` ✅（46 模块）；后端启动时进入页面会看到 toast「已连接 FastAPI：页面数据已从后端同步」
- **已知限制（明确记录，避免误以为已完成）**
  - Pulse 摘要数字（3/2/4/6）、Insight 的"原因/下一步建议"、图表数据仍是**页面内置演示语义**；正确归宿是后端 Insight Engine / `GET /api/insights/{id}` 详情扩展
  - `evidence` 内存映射未全量同步（证据抽屉已按 id 走 HTTP）
  - `capabilities` / `autoExpertNotes` 为前端静态演示内容
- **取舍说明**：不继续无脑把整份演示文案搬到后端；等 V2 引擎接管"判断"时，这些字段才会自然成为 API 契约的一部分
