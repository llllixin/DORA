## 4. 更新约定（写代码的人必须遵守）

1. 完成任一迭代 / change → 在 `docs/持续优化路线.md` 勾选对应 backlog 行（附可复现验证），并在 `docs/开发过程记录.md` 追加「迭代 N」。
2. 新增候选 / 关闭项 → 只改 `docs/持续优化路线.md`；不在其它文件复制清单。
3. 升级为正式版本（V6 或其他）→ 先在 `docs/持续优化路线.md` 加版本规划块（范围/任务/接口/验收/进入条件），命名在规划时定，本文 §2 随之刷新。
4. 反思 / 经验 → 只进 `docs/开发问题与经验.md`（P/D 系列）；归档历史不动。
5. V1–V5 的历史规划细节（§3A/3B/3C 等）以 `docs/历史版本路线.md` 为准，不再在本文维护。
