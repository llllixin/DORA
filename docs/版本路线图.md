## 3A. V3 · Dora Reasoning —— 详细规划（Planning）

> 定位一句话：**让"判断"保持确定性（引擎不变），只把"解释文案"从模板换成 LLM 生成。**
> 原则（D009/D014 衍生）：数值/判定/触发条件永不来自 LLM；LLM 只能引用引擎给出的事实来组织语言。

### 3A.1 范围与非目标
**范围（In scope）**
- 解释/总结/建议文本的生成来源抽象为 `ReasoningProvider`（引擎模板作为默认 provider，行为不变）。
- LLM Provider（OpenAI 兼容 chat/completions）：输入=引擎上下文（trigger/factors/evidence 行/metrics/semantics 现状），输出=与现契约一致的文案（desc/question/causeA/causeB/next/reason 的**文本部分**）。
- 语义缓存：新增 `insight_reasoning` 持久化（insight_id→payload+provider+generated_at）；`/api/insights` 内联语义先取缓存，无缓存回退模板并标注 `reasonSource`。
- 手工"重新解释"入口（前端按钮 + `POST /api/reason/refresh`）。
- 质量与降级：无 key/网络失败 → 自动回退模板（页面可见 `AI 解释失败，已回退模板`），绝不阻塞引擎输出。

**非目标（Out of scope）**
- Agent 编排 / 工具调用 / 多步推理（不进 V3）。
- Dora Chat SSE 对话流（另立能力）。
- 自动建档 action case / Watch 动态委托（V4）。
- 修改任何判定逻辑、规则、evidence 原始行。

### 3A.3 接口信息（V3 新增，均向后兼容）
```text
POST /api/reason/refresh
  body:  { }                       # 空 = 对当前引擎全部洞察逐条生成
  resp:  { ok:true, updated:[ids], fallback:[ids], provider:"llm|template" }
  # fallback = 未配置 key 或 provider 出错被模板接管的洞察；重复调用幂等（有缓存直接返回）。

（展示层仍走既有 GET /api/insights / /api/insights/{id}）
  # 语义字段不变：semantics{causeA,causeB,next,desc…}
  # 新增只读标注：reasonSource:"llm"|"template", generatedAt?:ISO
```
```text
环境变量（backend/.env）：
  DORA_REASONING_PROVIDER=template|llm   # 默认 template（无 LLM 也可全绿）
  DORA_LLM_BASE_URL=https://api.openai.com/v1
  DORA_LLM_API_KEY=…                      # 未设置 → 自动 template 降级
  DORA_LLM_MODEL=gpt-4o-mini
```
错误语义：LLM 侧 401/429/5xx → 该洞察回退模板（返回含在 `fallback`），API 本身返回 200；引擎端点不受影响。

### 3A.4 最终验收与审查计划
1. **功能验收**：打开任意洞察详情 → 可点"AI 解释/重新解释"；来源徽标正确；无 key/断网时自动回退模板并提示；刷新后缓存复用。
2. **判定不被污染（关键红线）**：provider mock 输入同一 context 输出不同文案时，断言 metric/delta/trigger/evidence/置信度**逐字段不变**（LLM 只动文本）。
3. **金样本/回归**：`DORA_REASONING_PROVIDER=template` 时 `tests/run_all` 全绿且 `/api/insights` 与 V2 结果一致。
4. **接口审查**：新增端点契约写入 openspec（V3 各 change 的 spec delta）；README 需求来源表同步。
5. **审查人核对项**：本规划 §3A、各 change 的 proposal/spec/design/tasks、`docs/开发问题与经验.md` D022+；大版本切换：验收通过后把版本速览 V3 标为已完成（记录迭代）。

### 3A.5 进入 V4 的判据
V3 验收清单全过 + 业务对象稳定 + Watch/Action 静态域说明仍有效时，再开 V4 planning（不提前）。
